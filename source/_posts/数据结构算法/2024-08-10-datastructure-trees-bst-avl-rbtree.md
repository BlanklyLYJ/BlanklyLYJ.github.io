> 这一篇把"自平衡二叉树"这条主线讲清楚:从最基础的二叉搜索树(BST)开始,讲清楚为什么它会被链表化、为什么需要 AVL、再讲到工业界更常用的红黑树。三者的核心区别、旋转规则、插入删除流程,以及它们各自的工程取舍,看完一次就能串起来。

## 一、二叉搜索树(BST):一切的基础

### 定义

二叉搜索树(Binary Search Tree,简称 BST)的要求:

- 任意节点的值 **大于左子树所有节点**
- 任意节点的值 **小于右子树所有节点**
- 左右子树各自也是 BST

中序遍历 BST 必然得到**升序序列**,这是它最重要的性质。

### 核心操作

| 操作 | 复杂度 | 说明 |
| --- | --- | --- |
| 查找 | O(log n) 平均 / O(n) 最差 | 比根节点小往左,大往右 |
| 插入 | O(log n) 平均 | 找到空位插入 |
| 删除 | O(log n) 平均 | 分三种情况 |
| 构建 | O(n log n) | 逐个插入 |

### 删除的三种情况

BST 删除最复杂,分三种情况处理:

1. **叶子节点**:直接删除。
2. **只有左子树 / 只有右子树**:用子节点顶上来。
3. **左右子树都存在**:找到**左子树最大值(前驱)** 或 **右子树最小值(后继)**,用它的值替换被删除节点,然后删除前驱 / 后继。

为什么是前驱 / 后继?因为这两个值在保持 BST 性质的前提下,最接近被删除节点的值,替换不会破坏规则。

### BST 的致命缺陷

BST 的复杂度是 **O(树高 h)**。如果插入顺序已经有序(比如 1, 2, 3, 4, 5),BST 会退化成链表,h = n,所有操作变 O(n)。

解决方案就是**自平衡**:让树高始终维持在 O(log n)。这就是 AVL 和红黑树登场的原因。

## 二、AVL 树:严格平衡

### 平衡因子

AVL 的核心约束:**任意节点的左右子树高度差 ≤ 1**。

定义平衡因子 BF = 左子树高度 - 右子树高度,AVL 要求 |BF| ≤ 1。

### 四种失衡情况与旋转

| 类型 | 插入位置 | 失衡节点 BF | 失衡节点子节点 BF | 解决 |
| --- | --- | --- | --- | --- |
| LL | 左孩子的左子树 | 2 | 1 | 一次右旋 |
| RR | 右孩子的右子树 | -2 | -1 | 一次左旋 |
| LR | 左孩子的右子树 | 2 | -1 | 先左旋左孩子,再右旋自己 |
| RL | 右孩子的左子树 | -2 | 1 | 先右旋右孩子,再左旋自己 |

**旋转的关键性质**:旋转后中序遍历不变。左旋时"冲突的左孩会变成右孩",右旋类似,二叉搜索性质被保留。

### 插入流程

1. 按 BST 方式插入。
2. 从插入点向上回溯,更新各祖先 BF。
3. 一旦发现失衡,根据上面的四种类型做对应旋转。
4. **插入只需调整一次**(最近的失衡祖先)就能让整棵树恢复平衡。

### 删除流程

1. 按 BST 方式删除。
2. 从删除点向上回溯,更新 BF。
3. 失衡则旋转。
4. **删除可能需要多次调整**:旋转可能让上层节点失衡,需要逐层向上检查到底。

## 三、红黑树:工程上最常用的平衡树

### 五条性质

红黑树在 BST 基础上引入"颜色"约束,保证近似平衡:

1. 节点是**红色或黑色**。
2. **根节点是黑色**。
3. **叶子节点(NIL 空节点)是黑色**。
4. **红色节点的孩子必须是黑色**(不能连续两个红)。
5. **从任意节点到所有叶子路径,经过的黑色节点数量相同**(黑高)。

这五条性质共同保证了:**最长路径不超过最短路径的两倍**,即树高 = O(log n)。

### AVL vs 红黑树

| 维度 | AVL | 红黑树 |
| --- | --- | --- |
| 平衡严格度 | 严格(\|BF\| ≤ 1) | 近似(最长 ≤ 2 倍最短) |
| 查找效率 | 更高(树更矮) | 略低 |
| 插入 / 删除旋转次数 | 多 | 少 |
| 适用场景 | 查找密集型 | 插入删除密集型 |
| 工程应用 | 数据库索引(部分) | STL map / set, Java HashMap, Linux 调度 |

工程上**红黑树更常用**,因为多数业务场景插入删除远多于纯查找,旋转少 = 性能稳定。

### 红黑树插入

插入按 BST 方式进行,**新节点默认是红色**(避免破坏"黑高相同"性质)。然后看叔叔颜色:

- **插入是根节点**:直接变黑。
- **叔叔是红色**:**叔父爷变色**,爷爷当作新插入节点继续判断。
- **叔叔是黑色**(或 NIL):判断 LL / RR / LR / RL 旋转,**对最后的旋转点和旋转中心点反色**。

### 红黑树删除

删除远比插入复杂,核心思路:

1. 按 BST 方式删除。
2. 红黑树删除只能容忍两种情况:
   - 删除的是红节点:直接删,不影响性质。
   - 删除的是只有单孩子(必然是黑)的黑节点:用孩子(必然是红)替换,变黑。
3. **删除的是黑色叶子节点**会破坏"黑高",最复杂。

约定**双黑色节点**:被删除的黑色节点让路径黑高少 1,把它的"黑色"叠加到它的位置上,变成"双黑"。删除完毕后**需要把双黑变回单黑**。

四种情况:

| 兄弟颜色 | 兄弟孩子颜色 | 处理 |
| --- | --- | --- |
| 黑 | 至少一个红 | LL / RR / LR / RL 变色 + 旋转 |
| 黑 | 全黑 | 兄弟变红,双黑点上移,继续判断 |
| 红 | / | 兄父变色,朝双黑方向旋转,保持双黑继续调整 |
| 双黑遇到红节点 | / | 红色变黑,搞定 |

最坏情况下需要从叶子一路调整到根。

## 四、其他常用树形结构速览

| 树 | 特点 | 用途 |
| --- | --- | --- |
| Trie 字典树 | 公共前缀压缩 | 字符串检索、自动补全 |
| B 树 / B+ 树 | 多路平衡 | 数据库索引(MySQL InnoDB) |
| 堆 Heap | 完全二叉 + 堆性质 | 优先队列、Top K |
| 哈夫曼树 | 带权路径最短 | 数据压缩 |
| 线段树 | 区间查询 | 区间求和 / 最值 |
| 树状数组 BIT | 前缀查询 | 逆序对、动态前缀和 |
| 并查集 DSU | 等价类合并 | 连通分量、Kruskal MST |

## 五、选型建议

```text
查找为主,几乎不增删           →  数组 + 二分 (前提:已排序)
顺序插入,需要中序遍历有序      →  BST(但要警惕链表化)
查找密集,插入删除少           →  AVL
插入删除频繁,要求综合性能      →  红黑树
海量数据,磁盘 IO 敏感         →  B+ 树
内存中键值对                  →  Hash 表(无序)/ 红黑树(有序)
范围查询 / 区间                →  线段树 / 树状数组
```

## 六、面试要点速记

- **BST 退化链表** → AVL / 红黑树登场。
- **AVL 严格平衡**,旋转多,查找快。
- **红黑树近似平衡**,旋转少,综合强。
- 红黑树五条性质 + **最长不超过最短两倍** → 树高 O(log n)。
- 插入默认红,叔红变色,叔黑旋转 + 反色。
- 删除黑叶子 → 双黑 → 看兄弟色和孩子色。
