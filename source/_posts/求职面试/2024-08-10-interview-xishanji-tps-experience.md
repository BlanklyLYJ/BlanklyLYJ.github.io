## 二、西山居解限机面经

### 技术一面(40 分钟,通过)

1. **UI 框架**:讲结构、讲优化、讲动效
2. **战斗框架**:讲优化、讲帧同步 vs 状态同步、讲定点数处理、讲逻辑/表现分离
3. **DOTS 理解**:ECS / JobSystem / Burst
4. **ECS 内存开辟规则**:16KB 一个 chunk,连续开辟
5. **JobSystem 线程安全**:`NativeContainer` 的 `ReadOnly`/`WriteOnly`,自己加锁
6. **List 底层**:数组
7. **Dictionary 底层**:数组 + hashmap 链表法
8. **委托**:类型安全的函数指针,多播委托
9. **Mask vs RectMask2D**:模板测试 vs 矩形剪裁
10. **协程实现**:上下文切换
11. 加班看法 + 反问工作流程

### 技术二面(电话,90 分钟,通过)

二面更偏场景和深度:

1. 之前公司规模
2. **UI 动效怎么做的、性能压力在哪**:压力主要在 Update,讲隔帧 / 异步加载
3. **内存优化**:GC 原理、装箱拆箱
4. **半圆背景图无限扩展**:九宫格
5. **九宫格实现机制**:这是渲染层的细节
6. **3D 场景血条参与遮挡**:深度排序 + 渲染顺序
7. **UI 锯齿问题**:抗锯齿方案
8. **机甲适合帧同步还是状态同步**:帧同步,因为飞弹多,必须实时计算
9. **帧同步 vs 状态同步区别**:服务端客户端分别做了什么
10. **帧同步预测差别大怎么办**:预测有极限,超限停止
11. **1 万人随机分 100 个玩家**:分组算法

机甲类游戏的同步问题我答得相对顺畅,因为解限机本身就是 TPS + 机甲,帧同步是必选项。二面电话 90 分钟,几乎把客户端所有模块扫了一遍。

## 三、跨品类的真实感受:6 个月 X 项目组总结

### 1. 工作绩效

X 项目组里我承担的任务:

- **luban 多语言扩展**:配置工具支持多语言字段
- **Google 登录 SDK**
- **数数科技 SDK**(数据上报)
- **新手引导**:FlowCanvas + 数据驱动
- **关卡与怪物投放**
- **交互物数据拆分**

反思:**新手引导的整体规划不够清晰,后续返工较多**;SDK 代码分离思路不够彻底。这是面试时被问"你最大的不足"的现成素材。

### 2. 跨品类的知识拓宽

TPS 项目 + ECS + 全 C# 开发,对我来说是**从语言到框架再到品类的一次全面拓宽**。以往做的多是卡牌/SLG 的业务,语言是 Lua;X 项目让我接触到 ECS 的世界观和全 C# 热更(HybridCLR)。

### 3. 工作流建议

提过的改进点:美术提交场景资源时,如果发生在开发时段会阻塞所有人拉 svn。建议美术把大资源提交放到下班前,提前通知,这样大家下班时让 svn 在后台跑,不影响开发时间。

## 四、散爆 TPS 面经精选

散爆的三面信息密度高,挑几个印象深的:

### 一面(30 分钟,基础扫荡)

- class vs struct / interface vs class / List vs Dictionary
- 怎么避免装箱拆箱(泛型、Struct 替代 Class、避免 object)
- 字符串修改发生什么(不可变,创建新串,用 StringBuilder)
- 弧形列表和滚动列表实现
- 项目协程用过吗,为什么不用(协程有额外 GC)
- Mask vs RectMask2D
- lua 和 C# 占比

### 二面(50 分钟,深度拷打)

- struct 里如果有接口引用字段,放内存哪里
- xlua 和 C# 怎么交互,数据怎么传递
- lua 引用数据,C# Destroy 后还能拿吗(空引用,会报错)
- lua table metatable 底层实现
- lua 继承实现
- Animator 状态除了代码条件还能怎么控制(参数触发)
- ab 包引用计数怎么判断可卸载
- Unity 四种 batch
- UI 合批原理:同图集 + 同深度 + 深度相邻 + 同 material + 同 texture,**不看是否重叠**
- 协程 `yield return 0` vs `yield return null`(前者有 GC,涉及装箱)
- 怎么判断角色是否在怪的正前方(向量点乘投影距离)
- 新手引导怎么做(行为树 or 配置表 + 编辑器获取按钮路径)
- 深拷贝怎么做(序列化反序列化、手动写、反射)
- 怎么知道 CPU/GPU 卡点(`Gfx.WaitForPresent` 长 ⇒ GPU bound)

### 三面(40 分钟,场景 + 算法)

- 快排实现、稳不稳定(不稳定)
- `virtual` 编译器怎么实现(虚函数表)
- Dictionary 底层 / hashmap 冲突(拉链法)
- Unity GC vs lua GC
- 红黑树 vs 平衡二叉树
- **场景题:1 万只怪、3 塔、每塔每秒 5 次攻击,怎么优化**(八叉树 + JobSystem + 分帧)
- 流场寻路算法(选中大量单位寻路时的优化)
- Unity 怎么知道 Mono 里的 Start/Update(反射读元数据)

## 五、点点 SLG 面经

- 资源加载框架

### 制作人面(40 分钟)

- 项目经历

## 六、跨品类转型的反思

### 1. 简历准备

JD 上每条要求,都要在自己的项目里找到对应模块能讲清楚的故事。优先准备两个故事:

- **框架**:UI 框架 / 资源加载 / 战斗框架,选一个深挖
- **优化**:UI 优化 / 战斗优化 / 内存优化,选一个有数据支撑的

### 2. 项目踩坑(面试硬通货)

整理的踩坑清单(节选):

- **新手引导**:被引导界面被盖住时该怎么做;主界面弹窗需要先加遮罩避免玩家跳过;FlowCanvas 驱动需要严格处理时序;战斗 UI 引导的点击透传
- **SDK**:strings.xml 打包、gradle 打包、android 调试
- **多语言**:按表格收集,中文引号、按表格处理缓存;不要让策划用配置再拦截打表(很繁琐)
- **HUD 自定义**:不要用表格硬配,搞工具直接导出;关闭用标志位而非 SetActive(false)
- **红点逻辑**:通用与简便的权衡
- **滚动列表**:必须先创建再处理显隐,不要定时器定时创建

### 3. 自我介绍模板

> 来自福建泉州,集美大学电科毕业。项目经历做过 MMORPG、卡牌类 SLG、模拟经营、率土 like SLG,也做过一个 VLS 类小项目。主要工作是业务开发、框架维护、编辑器开发、性能优化。参与过 UI 框架、战斗框架的开发,日常和策划、美术、服务端沟通出方案。喜欢玩游戏,期待做出一款自己主导的游戏。

### 4. 离职原因(口径)

> 1. 想休息一段时间,找后续方向,回去陪家人
> 2. 想去大城市接触新团队,接受新挑战
> 3. 原项目方向不明确
> 4. 想靠实力闯到一个陌生的地方

### 5. 职业规划

业务深入 → 框架深入 → 全面方向(主程),渲染了解原理,后续按项目需求决定深浅。

## 七、一点心态

求职这一轮下来,几个直观感受:

- **年限是硬门槛**:蛮啾要 5-10 年,差 0.01 年都卡
- **大厂简历挂很常见**:米哈游、鹰角的简历筛选残酷,内推是基本操作
- **三四面是综合面**:技术只是入场券,后面看沟通、文化匹配、抗压
- **不会就承认**:虚函数表编译期、BSP、漏斗寻路这些深问题,直接说"了解概念但没深挖"比硬答强
- **手撕代码别松**:链表奇偶重排、TopK、二分边界、状态机模拟,基础不熟就翻车

明年的我会笑不笑话现在的我,先闯出来再说。
