> 「游戏系统拆解」系列第三篇,拆 GOAP 慎思 AI。先交代背景:项目里有三套完全分离的 AI,按"思考成本预算"分层——城镇 NPC 用 GOAP 慎思(目标→规划→执行,2 秒规划一次),野怪用轻量 FSM(仇恨/拴绳状态机,每帧感知),同伴用 steering(槽位跟随,每帧)。三套互不共用组件,谁也不比谁高级,只是行为类型不同。本篇拆的是第一套:GOAP,以及整个项目里我个人最喜欢的一个设计——经济系统真实地改变 NPC 的决策。

<!-- more -->

## 一、定位:城镇 NPC 的长线决策引擎

先回答"为什么 NPC 要 GOAP"。

行为树(FSM/BT)回答的问题是"现在该做什么反应",GOAP 回答的是"我想达成什么、怎么达成"。对野怪来说,"看见玩家就追、贴身就打、拉远就回家"是完备的行为集,FSM 足矣。但对一个**要在城镇里过一整天**的 NPC,行为是长线且有目标的:药不够了要买药、没钱了要打工、夜里要回家、身体不舒服要休息——这些目标互相竞争,环境又在变(药店涨价了、下雨了),一张写死的行为树会把开发者钉在"穷举所有情况"的地狱里。

GOAP 的解法是把"目标"和"达成路径"分离:设计师只登记**目标**(期望的世界状态 + 优先级)和**行动**(前置条件 + 效果 + 成本),规划器(planner)负责在当前世界状态下搜索一条从现状通往目标的行动序列。新增一种 NPC 追求,不改决策代码,加一组数据就行。

这是 F.E.A.R.(2005) 提出的经典架构,后来在模拟经营和 RPG 里被反复验证:它的本质是把"NPC 智能"从代码问题变成数据问题——而数据问题是可以被策划持续填充的。

## 二、核心循环:Idle → Planning → Executing

三个系统按固定顺序每帧驱动:

```
AIWorldStateUpdateSystem(感知)
    每帧把实体真实状态同步进"世界状态"字典:
    LowHealth(HP < 30%) / IsDead / InCombat(攻击/受击态)
    HasGold / ShopStocksGoods(经济感知,实时药价)
    配置化谓词:IsNight、PlayerRich……(走全局条件引擎,见下)

GOAPPlanSystem(规划,每 2s 一次)
    1. 跳过:正在执行中 / 规划冷却中
    2. 选目标:遍历目标列表,跳过已满足的,取优先级最高者
    3. 做计划:对比目标期望态与当前世界状态的每个不一致键值对,
       生成行动入队
    4. 状态 → Executing

AIExecuteSystem(执行)
    行动进度 0 → 1(受缩放时间驱动)
    完成 → 出队 → 应用效果(写回世界状态字典)
    队列空 → 回到 Planning(下轮规划会看到行动成果)
```

一个完整时间线示例(NPC 满血但没金币,目标"有钱"):

```
t=0.0  [规划] 目标"有钱"未满足 → 行动队列 [打工, 领工资] → 执行
t=0~2  推进"打工"进度 → 完成,效果 HasGold=true
t=2~4  推进"领工资" → 完成,效果 GoldObtained=true
t=4.0  队列空 → 回 Planning;冷却中跳过
t=6.0  [规划] "有钱"目标已满足 → 换下一个未满足目标
```

注意一个容易误解的点:**世界状态是 NPC 自己视角的黑板(Dictionary&lt;string,bool&gt;),不是世界的客观镜像**。规划在"我以为的世界"上搜索,执行效果写回"我以为的世界"——这个设计让规划器完全不用碰真实游戏数据,搜索是纯内存操作,便宜且无副作用;真实世界的反馈通过感知系统在下一轮刷新进来。**规划用假想态,感知写真值**,两层职责分干净。

## 三、三个关键设计

### 3.1 感知分层:直算谓词 + 配置化谓词

感知(每帧把真实状态写进黑板)分两层:

**直算谓词**是代码写死的基础感知:血量、战斗态、位置、以及两个经济谓词——HasGold(agent 自己有没有钱)和 ShopStocksGoods(商店有没有货,**带实时药价的动态阈值**)。这些是高频变化的数值型判定,写代码里做缓存和直算最划算。

**配置化谓词**走全局条件引擎(PredicateBindings:谓词名 → 条件表达式列表,每帧求值结果写入黑板)。比如:

```
IsNight    ← time.Hour in 20-5
PlayerRich ← gold >= 50
```

这层的价值:**加一种感知不改 AI 代码**。策划在图编辑器的条件面板上配一条绑定,NPC 的世界观里就多了一个事实。而且 agent 与玩家共享同一个条件引擎的求值口径——"什么算夜间"对 NPC 和对剧情门控是同一个答案,不会出现"剧情觉得是夜里、NPC 觉得还是白天"的分裂。

一条**绑定铁律**必须记录:行动效果会写回的谓词(如 atForest、hasFirewood 这类"行动成果"),禁止配绑定——感知每帧覆盖,会把 NPC 刚挣到的行动成果抹掉,造成"永远在重复砍柴"的死循环。绑定只配"世界客观状态"(时间/天气/物价),行动成果只归行动效果写。这是黑板双写方(感知 vs 行动)的管辖权划分,越界就出灵异 bug。

### 3.2 经济融合:本系统的灵魂

单独把这个拎出来讲,因为它是"世界自洽运转"这条体验支柱的最硬核落地:

**NPC 买药的成本不是常数,是规划时实时查询的商店价格。**

```
L1 谓词层:HasGold / ShopStocksGoods / healthy(HP≥30%)
            ——agent 自身视角 + 实时药价动态阈值
L2 成本层:行动"买药"的成本 = Shop:<itemId>
            ——全场最低有货买入价,作为规划边权
L3 执行层:执行时找最便宜有货的商人真实交易;
            结算失败(钱不够/没货)→ 行动失败 → 重规划(不白嫖效果)
```

演示锚点:买药成本 11 vs 硬扛成本 16 → planner 选买药。玩家把药价炒上去(大量收购触发资金池规则,见商人经济篇)→ 下一轮规划,买药成本变成 21 → **planner 自动改选"硬扛"**。

没有人写一行"if 药价 > 20 then 换策略"的代码。NPC 的行为变化是三个系统(商店定价、GOAP 成本、规划搜索)各自按自己规则运转的**涌现结果**。玩家能通过市场行为影响 NPC 的生活决策,而 NPC 的决策又能被玩家观察到(他今天没买药,在硬扛)——这是"活的世界"和"脚本的世界"的分水岭。

### 3.3 反向桥:NPC 状态变成剧情可消费的数据

GOAP 的黑板不只服务于自己。条件引擎有一个 `flag` 谓词源,可以反读任意 agent 的谓词:

```
flag: 欧文:HasGold == true
```

也就是说剧情卡可以写一个门控:"当杂货商欧文自认为有钱时,这段对话才出现"。NPC 的内部状态(它的欲望、它的判断)成为叙事的一等数据源——"跟一个刚赚了钱的商人谈判"和"跟一个穷途末路的商人谈判",对话内容可以不一样。AI 与叙事系统在这里双向打通:AI 消费世界条件(配置化谓词进),AI 状态供剧情消费(flag 源出)。

## 四、数值与参数

| 项 | 数值 | 说明 |
|----|------|------|
| 规划间隔 | 2s(默认,可按实体配置) | 慎思频率;日程型 NPC 可以放宽到 5s+ |
| 低血线 | HP < 30% | LowHealth 谓词阈值 |
| 行动推进 | 进度 0→1,受 TimeScale | 时间暂停时行动同步暂停 |
| 演示成本锚点 | 买药 11 / 硬扛 16 | L2 边权示例 |

规划间隔是这套架构的"思考预算"旋钮:2s 意味着 NPC 对世界的反应最多滞后 2 秒——对城镇行为完全够用(没人要求 NPC 零延迟),而野怪的战斗反应(0.0x 秒级)交给 FSM,同伴的走位(每帧)交给 steering。**用不同的思考频率匹配不同的行为类型**,这是三套 AI 分层的根本依据。

## 五、系统关联

**上游**:

- 全局条件引擎——配置化谓词的数据源(12 个谓词源任选:时间/天气/金币/剧情变量……);
- 商人经济——药价/库存/资金池,是经济感知的真值来源;
- 属性/健康组件——直算谓词的血量来源。

**下游**:

- 条件引擎 flag 源——反向桥,剧情/事件消费 AI 状态;
- 商人经济——L3 执行层的真实交易(买入会真实扣 NPC 的钱、进商人的资金池);
- WorldState——长期记忆的落点(规划中)。

**联动回路**:商店定价 ← 玩家市场行为 → GOAP 成本变化 → NPC 决策变化 → NPC 交易行为 → 反过来影响商店资金池/补货。经济与 AI 构成一个闭环,玩家是这个闭环里最重要的扰动源。

## 六、设计取舍记录

**取舍一:黑板用 Dictionary&lt;string,bool&gt;而不是数值**。经典 GOAP 的世界状态就是布尔化,数值型判断(HP < 30%、gold ≥ 50)在感知层转成布尔再进黑板。代价是表达力(没法在黑板里直接比大小),换来的是规划比对的极简(目标态 vs 现状,逐键相等即可)和调试的直观(一张表看尽 NPC 的世界观)。数值的灵活性由配置化谓词的阈值侧承载,黑板上只落结论——**复杂度推到边界(配置),核心(规划)保持傻快**。

**取舍二:条件引擎是 GOAP 的数据源,不是规划器的判定器**。一个诱人的错误设计是把条件引擎直接接进规划器内部(搜索时实时求值)。这会让规划在"真值"上搜索,每个假想分支都要查一遍真实世界——昂贵,而且语义错乱(规划本该在假想态上推演)。正确的接入点是**感知**:条件引擎每帧把真值写进黑板,规划器只读黑板。管线单向,职责不混。

**取舍三:行动 ID 硬编码 0-3 起步**。四个演示行动(取目标/接近/攻击/逃跑)直接写成 int 常量,没上配置表。这是登记在册的技术债:**先让循环转起来证明架构,再数据化**——GOAP 的价值恰恰在于它数据化之后(行动表+成本+目标表)能被策划持续填充,但数据化的前提是骨架被验证过。债务不可怕,登记在册的债务不可怕,可怕的是忘了它为什么欠着。

**取舍四:失败重规划,不回滚**。行动执行失败(买药时钱不够了)的处理是"行动失败 → 整队重规划",而不是回滚已执行的前置行动。GOAP 原教旨里有回滚(撤销已应用的效果),但游戏场景里"部分完成的计划"大多有真实副作用(NPC 已经走到商店了),回滚既贵又不真实。接受"走两步冤枉路"的拟人感,放弃事务性——**NPC 不是数据库,半途而废本来就是活物的行为模式**。

## 七、开放问题与分期

| 问题 | 状态 |
|------|------|
| 行动/目标配置表化(替掉硬编码 0-3) | 登记的技术债,排期中 |
| NPC 日程(昼夜驱动作息:白天营业/夜间回家) | 规划——挂点在昼夜系统,GOAP 目标表加"按时就寝"类目标 |
| 情绪属性(Mood/Loyalty/Fear)作为目标权重 | 规划——情绪组件已存在,消费端待接 |
| 多 NPC 交互(交谈/借用/冲突目标) | 长线——涉及共享黑板的管辖权设计 |

## 验收批注(2026-09-25,第 03 篇)

**文档纠偏(读码核实)**:本篇"取舍三:行动 ID 硬编码 0-3 起步"与开放问题"行动/目标配置表化"**已过时**——GOAP 行动早已全面数据化:`GoapActionData`(SO:前置/效果/成本/时长/**动态成本源 CostSource**/**移动目标 MoveTarget**)+ `GoapAgentData`(目标/谓词绑定/行动库)+ **GOAP 可视化编辑器**(Tools/AI/GOAP 编辑器:行动/智能体双 Tab+按当前世界状态规划测试)。思维链(目标→前置分解→行动)的每一环均可配置可测试。

**用户拍板(2026-09-25)**:
1. **环境因素量化进 GOAP(条件层先行)**——agent 视角的"我在哪/现在几时"成为直算/绑定谓词,这是作息、野外行为分化的地基;
2. **作息是规划涌现,不是日程表**——"夜间回家睡觉"=目标(rested)+前置(atHome∧IsNight);夜行职业(夜市商人/盗贼/守夜人)用不同画像自然分化;"野外不能做药水打装备,第一个条件是回家/回城镇"由前置链表达;
3. 情绪(Mood/Fear)作为补充项**暂缓**;
4. 多 NPC 协作**留口子不实施**(GoapAgentData 类注释预留"外感知谓词"扩展,数据结构无破坏性改动)。

**实现(环境量化+作息涌现批次,5 文件)**:

- `WorldLocationRegistry`:+城镇语义(Register 带 townRadius;IsInAnyTown 判定);
- `GoapAgentData`:+HomeLocation 字段(作息锚点)+多 NPC 协作口子注释;
- `AIWorldStateUpdateSystem`:+atHome(距家<4m)/atTown(城镇半径内)/atWild 直算谓词——**位置真值权威**(行动效果写回是规划"声称",到达后自然归一,黑板防漂移);铁律注释名单同步+3;
- `GoapSeedData`:+Tools/AI/追加作息演示(环境量化)——4 新行动(GoHome/SleepAtNight/RunNightStall/StockStall)+2 画像(**Citizen 市民**:夜间回家睡;**NightVendor 夜市商人**:夜间进城摆摊/白天备货)+IsNight 时段绑定(条件引擎 time 源);
- `GameLaunch`:Town 注册带 12m 城镇半径。

**验证**(未编译,重开 Unity):Tools/AI/生成烧柴演示数据→追加买药演示→追加作息演示;把 Citizen/NightVendor 画像挂到 NPC;白天看规划链(GoTown→StockStall/Idle),20:00 后看市民 GoHome→SleepAtNight、商人 GoTown→RunNightStall。
