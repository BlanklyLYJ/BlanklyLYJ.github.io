## 一、定位:探索↔战斗的总开关

传统 JRPG 的战斗切换是「遇敌 → 黑屏/转场 → 战斗场景 → 打完 → 黑屏 → 回地图」。这个模式的问题不是老,而是**割裂**:战斗发生在"别的地方",探索和战斗是两个世界。

本作的设计立场:战斗发生在你站着的地方。开战被做成一段连续的演出——网格从脚下长出来、角色走入站位、镜头就位、然后开打。相位切换系统就是这场演出的总导演,它管的状态机只有一条主线:

```
None → Expanding(网格扩散,1s) → TransitionIn(战前走位) → Active(ATB 战斗)
     → TransitionOut(收场) → None
```

## 二、设计目的:消除割裂感的三个具体手段

**手段一:网格生长动画藏计算成本**。战棋盘不是预先摆好的,开战瞬间由参战单位的实际站位凸包生成(算法详见网格篇)。生成过程要做地形高度采样,3000 格约需 15 帧——把可见半径从 0 线性增长、高度分帧采样(200 节点/帧)全部藏在"网格扩散"的 1 秒动画里。**卡顿不是被消除了,而是被编舞了**——这是演出与工程互相迁就的典型样本。

**手段二:战前走位给玩家仪式感**。网格长出来后,单位并不是瞬间站好,而是各自走向最近的格子(1-2 秒)。这 1-2 秒有三个作用:玩家的眼睛有时间扫一遍战场(地形/敌我分布/高度差);节奏上完成从"探索的呼吸"到"战斗的专注"的切换;同时底层战斗数据已经写一致(见下文取舍)。

**手段三:战败不是终局画面**。打输了不弹 Game Over,而是横幅「撤退休整,敌人仍据守原地」然后切回探索——敌人保持残血待在原地,你可以回家补满再来。失败是战术事件不是进度清零(<mark>撤退与战败的完整设计仍是提案,见第 12 篇</mark>)。

## 三、核心规则全拆

### 3.1 遭遇检测:开战的两级缓冲

先回答"何时开战",再演出"如何进入":

- **遭遇触发**:玩家与遭遇区域水平距离 ≤3m 触发一次(IsTriggered 防重复);遭遇是**可预期的**——玩家看得见遭遇标记(红方块),走过去才触发,不是随机惊吓;
- **探索期贴身仇恨即开战**:野怪在探索期追到贴身,同样发开战事件——这是实时接战形态(C)的入口,与遭遇触发的战棋入口共用同一条开战管线;
- **门控**:UI 输入占用期(背包/对话全屏 dim)不开战——不是防打扰,是硬依赖:战棋操作要鼠标,全屏面板会挡死。

### 3.2 战前就位:先 Snap 后放回(本系统最重要的取舍)

战前走位期间角色在移动,但战斗逻辑(格子占用/六角坐标)必须**在走位开始前就写一致**:

1. 开战瞬间先把所有参战单位 Snap 吸附到各自最近格子,格子占用、HexPosition 全部落定——**战斗数据此刻已就绪**;
2. 然后把单位的**视觉位置放回原处**,让走位动画演"走进格子";
3. 距格中心 <0.15m 的单位跳过走位(没必要演);全员到达后兜底吸附,进 Active。

为什么这么做:如果战斗数据跟着走位动画走,PathFollow(路径跟随)任何一帧出错,战斗逻辑就站在错误的格子上。**视觉层可以演砸,数据层必须在开战瞬间就正确**——演出与逻辑解耦,这条原则在后续很多系统里反复出现。

### 3.3 相位切换的管线语义

相位不只是演出,它切换的是 ECS 管线的执行集:Active 期战斗系统组(ATB/战棋输入/战术移动/战术 AI)接管,探索系统组让位。这个切换是架构级的(详见 GameplayTag 篇的管线并发问题)——本篇只需要知道:**相位是开关,不是分叉**,三形态战斗(动作/战棋/接战)共用同一套战斗资产,相位决定哪套系统在跑。

## 四、数值速查

| 项 | 数值 |
|----|------|
| 网格扩散动画 | 1s(高度采样 200 节点/帧) |
| 遭遇触发半径 | 3m(水平距离,一次性) |
| 走位跳过阈值 | 距格中心 <0.15m |
| 战斗开/结束事件 | BattleStartEvent / BattleEndEvent(掉落/经验/遭遇标记/任务/音效全在这挂) |

## 五、系统关联

**上游**:遭遇注册表(重生状态机提供 ACTIVE/CLEARED)、怪物 AI(贴身仇恨)、UI 门控。
**下游**:BattleStartEvent 的订阅者掉了一串——掉落系统、经验结算、遭遇标记写 Cleared、任务 kill 目标、战斗音效;BattleEndEvent 同理。
**联动**:网格动态扩展(演出的主体)、ATB(就位期间不充能——不能白嫖走位时间)、同伴系统(开战时清非参战者速度,防止冻结冲刺速度被持续积分成漂移)。

## 六、设计取舍记录

**取舍一:编舞 vs 优化**。网格生成的性能问题有两条解法:优化算法(快到不需要藏)或藏进动画。选了后者+基础优化——因为"棋盘从脚下长出来"本身就是想要的画面,一石二鸟。<mark>渲染增量的 P1 优化、脱战网格回收的 P2、独立脱战判定 P3 都还是待定项</mark>。

**取舍二:网格收起动画未做**。战斗结束的网格是直接消失的,靠横幅+音效补偿节奏感。诚实记录:收起动画在"想做"清单里,优先级排在可玩内容之后。

**取舍三:转场拒绝开战而不是排队**。UI 占用期遇敌直接不开战,而不是"关面板后自动开"。排队的复杂度(队列状态、时序竞争)配不上它的收益,玩家走两步再触发一次没有成本。
