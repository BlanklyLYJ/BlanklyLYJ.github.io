## 一、交互系统:跨上下文的桥

**定位**:玩家与世界物体近距离互动的唯一入口——对话、商店、营火、拾取、扶起,全部从这一个入口进。它是少数跨 Context 的系统(读 InputContext 的按键,查 GameContext 的实体)。

### 核心规则

```
检测:Confirm(E)按下 → 找最近可交互物(IsAvailable ∧ 距离 ≤ Range,默认 2m)
执行:0.3s 起手(面向目标+站定+白闪)→ 结算
打断:受击/死亡/入战打断起手;死亡/硬直/翻滚态不可起交互
```

结算按类型分发:

| InteractType | 结算 |
|--------------|------|
| Talk | 场景卡(剧情管线) |
| Shop | 开店(压输入上下文栈) |
| Camp | 营火面板(烹饪+睡觉) |
| Pickup | 入包+销毁目标实体 |
| Revive | 扶起同伴(倒地交互) |

**0.3s 起手是塞尔达式的确认节奏**——不是防误触的技术需要,是"我在做一件事"的体感传达(探索动作层 6.6 节同款)。所有交互类型共享这 0.3s,**世界的响应节律是统一的**。

**动态开关**是交互系统的隐藏能力:InteractableComponent 的 IsAvailable 可运行时切换——同伴平时屏蔽交互(非对话对象),倒地时切换为 Revive+可用(Prompt="扶起:维克多"),恢复后切回屏蔽。**交互的可用性是实体状态的表达,不是静态配置**。

### 数值速查

| 项 | 数值 |
|----|------|
| 默认交互距离 | 2m(营火/商店各有定制) |
| 起手时间 | 0.3s |
| 商店交互距离 | 2.5m |
| 检测方式 | 最近者优先(同帧多目标取最近) |

## 二、教程系统:框架就绪,内容未铺

**定位**:引导步骤的推进器,运行在 UIContext(与 GameContext 分离——教程是 UI 层的状态)。

```
状态机:None → Active → Completed
步骤:按 StepIndex 推进,CompleteStep 标记完成
完成:所有步骤 IsComplete → CompleteTutorial → 发事件
```

- **步骤完成条件 = 组件状态检查**(如"移动速度>0"=玩家移动了)——教程的验证不靠计时器靠**行为的真实发生**;
- 引导期输入上下文锁定(防玩家在教学时乱按触发别的系统);
- **现状:框架就绪,内容零铺设**——demo 后期填充。<mark>这是"骨架先行"节奏的标准案例:教程框架与游戏内容并行开发,内容定型前不铺教程(铺早了内容一改全重写)</mark>。

## 三、系统关联

**交互**:上游输入(E 键/上下文门控);扇出——对话/商店/营火/拾取/扶起、任务系统(talk 目标消费 InteractCompletedEvent)、掉落(拾取路径之一)。
**教程**:上游 UIContext;扇出——引导期的输入锁定。

## 四、设计取舍记录

**取舍一(交互):最近者优先而非列表选择**。近距离多目标时弹列表选(塞尔达旷野之息的复杂场景用)精准但打断节奏;最近者优先(离谁近跟谁交互)零 UI 成本,靠空间选择(你走到谁面前就是谁)。俯视角下玩家的空间控制是精确的,空间即选择器。

**取舍二(交互):起手可打断而非动画锁定**。锁定(起手后必完成)防刷但僵硬;可打断尊重战斗的突发性(被打断的交互不产生任何效果——0.3s 白干)。交互是低风险行为,打断的代价轻,流畅优先。

**取舍三(教程):状态检查而非事件驱动**。事件驱动(等"移动按键按下"事件)精确但每个教程步骤都要接专属事件;状态检查(查"玩家在移动吗")通用但轮询。教程步骤的验证条件本质都是"世界处于某状态",状态检查天然匹配。
